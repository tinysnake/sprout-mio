# UI 开发专项计划

按本文交付与 [功能开发计划](development-plan-functional.md) 对齐的 UI 设计和演示前端。先建立设计基础，追赶 P1、P2 和 P3，再随功能章节交付。跨线调度、真实服务接入、反馈修复与整体验收由 [开发总计划](development-plan.md) 协调。

本文已记录讨论确定的范围与顺序，任务均待执行。参考图已收集，设计语言与 token 是下一步。文档完成、工具接入试作和示例截图均不代表正式设计或 UI 阶段已经完成。

## 沿用功能章节安排交付

按功能计划的大章节设置 UI 交付与集成里程碑。P4 沿用已有的 a 至 d 小节，P5 对应多人 Chat 与 Task 协作两个小节。章节内可以拆设计任务、组件任务和代码提交，不因每个小任务完成而新增一次集成。

| UI 阶段 | 对应功能范围 | 前置条件 | 交给集成线的时点 |
| --- | --- | --- | --- |
| UI 基础 | 跨页面设计语言、token、布局和基础组件 | 已确认的目标与参考图 | 经样板验证后随基础追赶包交付，不单设产品集成 |
| UI-P1/P2 追赶 | P1、P2 的已有页面与操作 | UI 基础 | 整个基础追赶包就绪后集中集成 |
| UI-P3 追赶 | P3 真实对话与宿主仓库入口 | 基础追赶包集成通过，P3 契约可供核对 | 按完整 P3 集成 |
| UI-P4a | Worker 连接与 Project 绑定 | UI-P3 集成通过，P4a 契约就绪 | 按 P4a 集成 |
| UI-P4b | 分身持租与远端操作 | P4a 集成通过，P4b 契约就绪 | 按 P4b 集成 |
| UI-P4c | 长命令、日志、结果与恢复 | P4b 集成通过，P4c 契约就绪 | 按 P4c 集成 |
| UI-P4d | 交接、收回与 Machine 移除 | P4c 集成通过，P4d 契约就绪 | 按 P4d 集成 |
| UI-P5a | Group、Public Channel 与多人协作 | 已有 Chat 设计，P5a 契约就绪 | 按 P5a 集成 |
| UI-P5b | Task 协作 | P5a 集成通过，P5b 契约就绪 | 按 P5b 集成 |
| UI-P6 | 自动接续、Info Hub 与成员治理 | P4、P5 集成通过，P6 契约就绪 | 按完整 P6 集成 |
| UI-P7 | 手机、PWA、恢复与一期完整体验 | P6 集成通过，P7 范围明确 | 完成一期整体验收 |

表中“集成通过”指章节已通过技术验收。章节只有经 Human 亲自体验并明确确认后才算完成；人类体验确认不作为后续章节开工的必要条件，Human 明确 AFK 时可推迟体验验收。设计尚未经 Human 确定时，可以继续草案与功能开发，但不满足正式集成的 UI 交付条件。具体规则见 [开发总计划](development-plan.md)。

默认按功能计划顺序推进，功能计划允许的跨章并行由开发总计划明确安排。当前章节交付并通过技术验收后，再推进依赖它的章节。设计与功能问题在开发中及时反馈，正式接入和验收集中在章节里程碑。一轮章节集成可以包含多次修正与复验，仍计为同一个里程碑。

## 先追赶已有功能

将 P3 作为需要完整追赶的阶段安排。执行前核对功能阶段记录、已合入代码和实际契约，记录所用的 commit、未完成项与已知限制。P3 尚在开发时采用已稳定部分，等待本章范围就绪后整章集成；P3 已收尾时沿用其实际交付范围与部分交付限制，不将限制自动扩大为 UI 追赶中的补做任务。

先交付 UI 基础与 P1/P2 基础追赶包，再完成 UI-P3 追赶。P1/P2 合成一次集成，P3 单独进行一次整章集成。P3 内部的 session、轮次、仓库和 Info Hub 开发任务不分别设置集成里程碑。

UI 计划确定后，按开发总计划暂停开启新的功能章节，在途任务收口到可验证、可交接的位置，记录实际停点。功能线继续处理集成反馈、已有缺陷与必要适配。P1/P2 基础包集成保留已有 P3 能力，P3 追赶通过技术验收后恢复新增功能开发，人类体验确认独立记录。本文件不直接停止其他执行者的任务。若功能线已经继续推进，先记录差异，再由开发总计划安排，不把新范围自动并入 P3 追赶包。

## 使用设计工具生成并迭代

每个章节按同一流程交付。

1. 助手读取对应功能章节、实际契约和已有设计，准备目标、范围、参考图、页面状态、响应式要求与交付物组成的提示词。
2. Human 将提示词交给 OpenPencil、OpenDesign 或当时选用的工具，由工具生成初稿。可以在不同工具中尝试，不设必须通过的工具对比阶段。
3. Human 在工具中微调。助手根据产物和反馈修订提示词、检查遗漏，并整理已确定的设计规则。
4. 完成章节内各页面与组件设计，检查主题、状态、信息层级和共享布局的一致性。用到现有规则的新场景先扩展组件变体，确有需要再新增组件。
5. 将确定的设计实现或整理为可操作的演示前端。检查工具导出的代码与项目 React、shadcn + Base UI 约束的适配情况，补齐导航、页面交互和示例状态。
6. 保存设计源文件、token、组件、演示代码、截图或录像、操作说明及已知限制，向集成线交付整个章节。集成反馈回到对应设计或演示代码任务修正。

工具中的生成、助手通过 MCP 直接搭建和人工编辑分别记录，不把接入实验当作工具生成质量的证明。长期工具选择依据实际设计与修改体验，不要求每个页面都经过两个工具。使用多个工具时，记录设计源文件与 token 的维护位置，避免维护多份互不一致的规范。

## 保持已确认的体验方向

- 将 Chat 作为主要工作区，Task overview 作为第二个高频界面。配置与管理页面采用一致布局，按需展示详细信息。
- 宽屏 Chat 工作区采用左侧列表、中间详情和右侧 inspector。Inspector 展示当前上下文的 Info Hub 信息，聊天内容获得主要空间。
- 窄屏先显示 Chat 列表，进入详情后通过返回回到列表。Inspector 通过明确入口打开，URL、当前对象和返回语义保持一致。
- 一级导航沿用 Projects、Agents、Machines、Management，不新增 Feed 或独立 Info Hub 一级入口。导航与三栏工作区的具体组合在共享布局阶段确定。
- 使用清晰克制的视觉语言。以中性色为底，少量强调色用于操作、选中和必要状态，通过字号、字重、对比与间距区分主次。
- 同时设计浅色、暗色主题。两者沿用相同组件结构和语义，分别检查文字、边界、选中、聚焦及错误状态的可辨识程度。
- Header、导航、工具栏、列表项、表单和信息分组采用共享组件与明确变体。各页面填充内容，避免分别实现高度、间距和对齐规则。
- Task overview 按 proposed、assigned、finished、canceled 分栏，卡片只展示少量一级信息，详情按需打开。卡片具体字段在 UI-P5b 确定，不增加 Task 执行状态。

## 交付演示前端与章节材料

每个业务章节交付设计与基本功能演示。使用固定示例数据和页面内临时状态，刷新后恢复样例，无需数据库、真实 Pi、Worker 或业务 API。示例演示只证明 UI 行为，真实授权、持久性、执行和恢复由集成验收证明。

演示支持章节主要路径、必要的导航、表单反馈与状态切换。加载、空数据、处理中、成功、失败、断线、旧数据、未实现和未知按该章节契约选用，不为所有页面机械添加全部状态。用独立示例场景演示失败与恢复，避免将模拟状态显示为真实执行结果。

每章交付时记录以下内容。

- 对应功能章节、基线 commit、依赖契约及未完成或有分歧的字段。
- Human 调整后的设计源文件版本、token 与共享组件的维护位置。
- 页面、URL、用户操作和状态清单，以及各状态的真实数据来源或待接入点。
- 可启动的演示代码、实际运行命令、示例数据与场景切换方式。
- 浅色、暗色、宽屏、窄屏截图，以及主要操作录像或可复跑的浏览器步骤。
- UI 自检结果、已知限制、待集成事项和反馈修复记录。

设计文件和演示代码支持版本记录，资源与依赖在交付说明中列明。代码进入项目时沿用 [P1 开发约定](p1/conventions.md)，目录、允许修改的文件与负责人在执行任务中明确。设计线负责呈现与演示交互，真实业务逻辑和协议仍由功能线维护，正式服务接入由集成线负责。

## UI 基础 建立设计语言与共享布局

本阶段先确定第一版规则，用 Chat 样板验证后交付基础追赶包。仅构建当前页面需要的基础，后续随功能章节扩展。

- [ ] 整理 design brief，记录主工作区、参考图、信息密度、布局偏好和一期边界。
- [ ] 按工具协作流程生成并微调第一版设计语言，确定颜色、文字层级、间距、圆角、分隔、图标和状态表达。
- [ ] 建立基础 token 和语义 token，包含浅暗主题、别名与使用规则，保存可版本管理的 token 文件及代码可用的样式表示。
- [ ] 设计应用导航、各页自己的页面标题区（返回上一级链接、`<h1>` 标题与一句说明）、列表与详情、三栏工作区、inspector、表单与操作反馈，明确组件变体、内容插入位置和窄屏行为。
- [ ] 用 Chat 样板检查文字阅读、长内容、消息输入、信息展开、主题和屏幕变化，修订不适用的规则。

出口条件是 Human 确定第一版设计方向，共享布局与组件可以供 P1/P2 使用，token 有明确维护位置与浅暗对应关系。完成本阶段不代表 P3 真实对话或其他业务已经接入。

## UI-P1/P2 追赶基础页面与持久对话

范围对应 [P1](development-plan-functional.md#p1-建立可重复的工程骨架) 和 [P2](development-plan-functional.md#p2-建立身份成员与持久对话)。先实现共享布局和 DM 样板，再补低频页面，整个章节完成后交付一次基础集成。

- [ ] 完成登录、最小初始化、已登录入口、Project 创建与 `/projects` 分发设计及演示：账号注册时创建默认 Project「我的项目」；`/projects` 在只有一个 Project 时直接进入其 Chats，零个时显示新建入口，多个时才显示列表，Project 列表页不作为导航目标；Project 详情页已删除，Project ID、创建时间等基本事实并入 Project settings；侧栏 Projects 仅作为二级菜单折叠开关，不作为导航项，侧栏和移动端二级菜单均只有 Chats、Members、Project settings 三项，Project 选择器不提供「查看全部 Projects」入口。
- [ ] 完成 Project 配置、Agent profile 列表与详情、成员添加与移除的设计及演示，包含职位（`jobTitle`）字段编辑：可留空、最多 40 字，仅展示分工，不承载任何权限语义，空值不显示徽标；`role` 保留给二期项目级权限层级，不用于指代职位；Agent 详情页的 model 与 effort 均为含「使用默认」选项的下拉字段，留空即沿用宿主默认。
- [ ] 完成 Chat 列表、持久 DM、分身与人设信息、消息阅读与发送演示。
- [ ] 完成已有 Info Hub 信息在页面及 inspector 中的展示与关联入口，后续阶段能力明确保留未实现语义。
- [ ] 检查稳定 URL、刷新、前进后退、窄屏列表进入详情与返回，以及字段校验、请求失败和无权查看场景的 UI 表达。
- [ ] 检查各页自己的页面标题区、布局与组件使用一致，保存浅暗主题和宽窄屏证据，交付章节材料。

出口条件是已有 P1/P2 能力都有对应设计和可操作演示。集成时验证真实登录、保存、分身与消息持久性、URL 和两用户隔离，沿用既有行为断言。上述真实行为通过技术验收后，进入依赖它的 UI-P3 追赶；基础包完成仍须 Human 体验确认。

## UI-P3 追赶真实对话与宿主仓库入口

范围对应 [完整 P3](development-plan-functional.md#p3-跑通真实-pi-对话和仓库入口)。采用实际交付的 run、输入和仓库契约，整章交付后集成。

- [ ] 补齐 Human 与 Agent 消息、运行状态、当前轮追加消息和停止的设计及演示。区分未投递、已投递和运行结果，不以发送成功替代处理完成。
- [ ] 补齐宿主未启用、未开始、排队、运行中、停止、失败及重启中断等实际状态，提供错误详情与 requestId 的适当入口。
- [ ] 补齐 profile 修改从下一轮生效的提示，保持同一 Chat、分身和历史的连续性。
- [ ] 补齐宿主仓库配置、复用副本、按需获取、获取中与失败反馈，以及来源、ref、commit 和获取时点的概要与详情。
- [ ] 在 inspector 与相关页面呈现 Agent status、活动 runs、错误和仓库依据，区分当前事实与轮初快照，低频细节按需展开。
- [ ] 完成跨页面演示与章节交付材料，核对 P3 全部 UI 范围，不按内部开发任务拆集成。

出口条件是用户可演示从仓库配置进入 DM 分析、查看回复、追加消息、停止和错误处理的路径。集成线用真实 Pi 验证同一条路径及重启行为，确认页面状态与实际运行、投递和仓库来源一致。

## UI-P4b 展示分身持租与远端操作

范围对应 [P4b](development-plan-functional.md#p4b-实现分身持有与远端操作)。

- [ ] 完成租约与 holder 的概要、详情、申请和释放反馈，以及分身持有多台 Machine 的展示。
- [ ] 展示远端 shell、文件和进程操作的目标与结果，区分宿主与指定 Machine，不新增完整终端或文件管理产品。
- [ ] 在 Chat、Machine 详情与 inspector 中一致呈现持租事实，run 结束后不自动显示租约已释放。

出口条件是租约、分身、run 与操作目标可清楚区分，申请和释放有结果反馈。集成时核对互斥、跨 run 持有、授权失败和 Project 边界。

## UI-P4c 展示长命令与不确定结果

范围对应 [P4c](development-plan-functional.md#p4c-实现长命令与不确定结果)。

- [ ] 完成执行详情、运行状态、日志读取、退出结果和取消反馈的设计及演示。
- [ ] 完成日志续读、达到保留限制、断线、重连与结果未知的呈现，明确当前信息是否完整。
- [ ] 保留稳定 execution 定位，页面恢复后可以继续查看既有执行，未知结果不提供会隐式重跑原命令的操作。

出口条件是长命令的当前事实、日志完整性和未知结果可辨识。集成时验证真实命令跨 run、断线与重启后的查询和取消行为。

## UI-P4d 完成交接收回与移除交互

范围对应 [P4d](development-plan-functional.md#p4d-实现交接收回与-machine-移除)。

- [ ] 完成向指定分身交接、Human 强制收回和 Machine 移除的交互、警告与确认。
- [ ] 呈现授权变化、离线待处理和无法确认撤权的状态，相关页面与 inspector 更新为同一事实。
- [ ] 说明交接、释放与收回对既有执行的实际影响，避免让用户误以为租约操作会清理进程或文件。

出口条件是操作前后 holder 与权限变化明确，待处理不会显示为成功。集成时验证旧 holder 失权、新 holder 接续查询与带租约移除的真实结果。

- [ ] 完成 Group 创建、成员管理、owner 指定与变更，以及 Public Channel 成员自动同步的设计及演示，操作范围遵循产品决定。
- [ ] 扩展消息列表、发送者识别、多 Agent 活动与成员回报，保持主要聊天内容清楚，避免堆叠所有运行细节。
- [ ] 在 header 和 inspector 中呈现成员、owner 与活动 runs 的关联，支持查看相关对象。

出口条件是用户可演示建立 Group、设置 owner、多人消息与回报，以及 Public Channel 的成员关系。以完整 P5a 进行集成，不按成员和消息分别集成。

## UI-P5b 完成 Task 总览与生命周期

范围对应 [P5b](development-plan-functional.md#p5b-完成-task-协作)。

- [ ] 设计按 proposed、assigned、finished、canceled 分栏的 Task overview，确定卡片一级信息、空列、长标题和窄屏浏览方式。
- [ ] 完成 Task 详情、创建、分配给 Chat、可选立即开始、完成、取消、人类纠正与重开的设计及演示，具体迁移规则沿用功能契约。
- [ ] 完成 checklist、施工记录及末条记录中的完成结果，提供回到承接 Chat 和相关对象的入口。
- [ ] 在 Chat 与 inspector 中呈现 Task 关联，分别表达 Task 状态、run 活动与租约事实。

出口条件是用户可在演示中从分栏总览进入 Task，分配给 DM 或 Group，并完成记录、完成与重开路径。整节集成验证真实 Task 生命周期，不新增运行中 Task 状态或独立强制验收流程。

## UI-P6 完成自动接续与成员治理呈现

范围对应 [P6](development-plan-functional.md#p6-完成自动接续info-hub-与成员治理)，暂按整章交付。

- [ ] 完成自动接续状态、人类暂停与停止、失败反馈及恢复控制的呈现，保持 Task、run 与自动检查语义独立。
- [ ] 补齐 Info Hub 的 Project、Chat、Agent、Machine 一期视角，设计当前事实、轮初快照和更新提示的层级，不把全部字段默认展开。
- [ ] 完成 Agent 移除前置检查、阻塞原因与关联处理入口，以及正常移除后的 Group 退出、DM 归档和重新加入的恢复呈现。
- [ ] 核对普通信息可见性与聊天正文访问、对象操作权限的区别，完成全章演示和交付材料。

出口条件是自动接续与人类控制的关系清楚，信息视角一致，成员治理有明确阻塞和恢复反馈。整章集成验证自动行为不抵消人类控制，移除后的授权真实生效。若 UI 范围扩大到难以整章交付，先提出拆章建议，经讨论后同步功能与 UI 计划。

## UI-P7 完成客户端与一期体验验收

范围对应 [P7](development-plan-functional.md#p7-验收完整一期与客户端体验)。此前各章均需提供浅暗主题和宽窄屏交付，本节补齐设备差异与完整使用路径。

- [ ] 检查 Projects、Agents、Machines、Management 的导航、共享布局、主题切换和各入口的实际可用性。
- [ ] 检查详情深链、刷新、前进后退、登录后目标恢复，以及窄屏列表、详情、inspector 的进入与返回。
- [ ] 补齐 PWA 安装与独立窗口体验、断线、旧数据和重新进入后的同步反馈，不默认离线排队操作。
- [ ] 在真实手机检查输入区、软键盘、滚动与主要操作，明确浏览器视口模拟与真机证据的区别。
- [ ] 配合集成线完成一期七步开发闭环和故障场景，检查页面不将未知、失联或未支持能力显示为成功。

出口条件是一期主要使用路径和必要异常路径有真实浏览器及设备证据，已知限制可定位。模型、Worker、恢复与授权的行为结论以对应集成证据为准。

## 按章节检查完成证据

设计确定、UI 演示通过、真实集成技术验收通过与 Human 体验确认分别记录。只有本节要求的材料存在后才勾选 UI 任务；集成技术验收通过后记录技术结论，只有 Human 亲自体验并明确确认后，才由集成线记录章节完成。

每章检查共享组件与 token 的使用、信息主次、浅暗主题、宽窄屏、键盘焦点、表单反馈、主要导航和必要异常状态。视觉变更保留截图，交互保留录像或可复跑的浏览器步骤。更新已有验收定位时保留身份、持久性、授权和状态含义的行为断言。

本文件只安排一期。P8 二期与 R1 研究涉及的 UI，在功能范围确定后追加对应章节。后续任务若需要新增页面或改变已确认的布局与业务语义，先记录影响，再同步相应计划和产品决定。
