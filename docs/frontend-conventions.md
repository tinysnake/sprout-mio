# 前端开发约定

状态：本约定立即适用于新增和修改的前端代码。存量页面与 shadcn 默认组件随 I-P1/P2 迁移收敛，不能因存量存在违规写法而新增一份。本文不表示静态门禁、组件演示或页面迁移已经完成。

设计依据见 [前端设计基线](frontend-design.md)，业务边界与工程规则沿用 [P1 开发约定](p1/conventions.md)。编排必须从 [开发总计划](development-plan.md)进入。

## 开工时先确定复用对象

前端任务先读本约定、设计基线、对应业务契约，以及将修改的组件和验收脚本。任务说明至少明确：

- 对应集成单元、本次用户路径与不包含的功能。
- 复用哪些布局和基础组件；新增变体或组件的具体原因。
- 数据、操作与错误来自哪个现有契约；哪些只是演示数据。
- 受影响的主题、宽度、键盘操作和异常状态，以及准备保留的验证证据。

不要因准备任务说明而停下来等待额外审批；在已授权范围内完成常规选择和实施。遇到尚未确定的设计分歧，将其具体记录为待确认，继续处理不依赖它的工作。

## 目录与代码边界

| 位置 | 职责 |
| --- | --- |
| `src/theme.css` | 基础及语义 token、浅暗对应值、Tailwind 主题映射的唯一所有者 |
| `src/styles.css` | 样式入口、字体导入、全局 reset 与 base 规则 |
| `src/components/ui/` | 基于 shadcn + Base UI 的无业务基础组件，如 Button、Dialog、输入和菜单 |
| `src/components/layout/` | 应用侧栏、页面标题区、工作区分栏与响应式布局；迁移时建立 |
| `src/components/<feature>/` | Chat、Agent、Project、Info Hub 等业务呈现与操作组件 |
| `src/routes/` | 文件路由、认证入口、loader、导航与页面组合 |
| `src/dev/` | 共用正式组件的开发演示、固定 fixtures 与场景入口；迁移时建立，不进入正式产品导航 |
| `scripts/browser/`、`tests/` | 浏览器行为、布局与必要回归验证 |
| `docs/` | 规则、交付记录、截图证据与已知限制 |
| `design/archive/` | 冻结的历史原型；正式应用不导入，不继续开发 |

命名沿用 kebab-case 文件、PascalCase React 组件、TypeScript 和现有导入约定。不要为了 UI 迁移新建独立产品 package、第二套路由应用或另一套组件库。

## Tailwind 与 CSS

1. 组件使用 Tailwind 工具类和语义颜色，如 `bg-background`、`text-muted-foreground`、`border-input`、`bg-primary`。不在组件写 hex / rgb / oklch 色值，不使用 `text-gray-*` 等另起色板，也不引用 `--bg`、`--fg` 等基础色板绕开语义层。
2. `src/theme.css` 定义颜色及可复用的设计 token；`src/styles.css` 不成为第二个 token 文件。新增公共 token 时一并说明语义、浅暗对应和实际使用者，不为单个 margin 建 token。
3. 常规布局、间距、字号、状态与响应式优先使用 Tailwind。重复的样式和行为归入共享组件及 cva 变体，不通过复制一长串 class 维护多个 Button、Field 或菜单。
4. CSS 仍可用于复杂选择器、滚动与 reduced-motion 等全局规则，以及工具类难以清楚表达的布局。局部 CSS 应与所属组件放在一起并限制作用范围，不能复制原型整份 app.css 或建立全局组件样式大杂烩。
5. arbitrary value 可表达有依据的几何值或布局计算，不能用于偷塞新色板、另一套圆角或绕开共享变体。动态 inline style 限于拖拽宽度、测量视口等运行时数值；静态外观通过组件类和 token 表达。
6. 跨主题的颜色变化优先由 token 处理；`dark:` 可表达主题确实不同的呈现细节，不能让每个页面重写整套颜色。禁止把 `bg-accent` 当作中性 hover，使用 `bg-hover` 或相应组件变体。
7. 调整公共组件从该组件自身及演示入手，不能在页面用 `!important`、任意后代选择器或连续 class 覆盖把它改成另一种按钮。迁移中的临时差异记录到章节材料，完成后移除。

## 组件与状态的归属

- 基础组件不读取业务 API、数据库或路由上下文。优先复用现有 shadcn + Base UI 的交互基础，将视觉适配成 Mio 变体；不能直接把新生成的默认组件当成定稿。
- 菜单、Dialog、选择器复用基础库提供的键盘、焦点与关闭行为，不照抄原型手写的 document click 监听实现第二套机制。原生 input / textarea / select 在满足统一外观和行为时可以使用，不为一致性强制替换成复杂控件。
- 可演示的页面主体通过类型化 props 接收数据，通过回调提交用户意图。路由或已有业务操作组件负责服务调用和成功后的同步。按实际复用与状态边界拆分，不为每个组件机械增加 container、adapter 或全局 store。
- 演示与真实页面必须使用同一份呈现组件。演示提供 fixture 和模拟操作回调，真实页面接现有 server functions；不维护 `DemoAgentForm` 与 `RealAgentForm` 两份相同界面。
- URL 拥有当前 Project、Chat、对象详情等可定位目标，使用 TanStack 路由。组件本地状态用于折叠、草稿、pending 等交互，不能拿全局 currentProject 替代 URL 或服务端授权。
- localStorage 只保存明确允许的界面偏好，读取兼容缺失或损坏值，访问 window / document 时遵守应用运行边界。不能用浏览器缓存伪装业务持久化或授权。
- 业务事实以契约和服务结果为准。UI 可以显式转换为展示模型，不发明一套与 run、消息投递、权限或租约含义不同的状态机；不能用 setTimeout 自动把请求变为成功。
- pending 时防重复提交，失败保留草稿，成功后按现有路由同步机制读取事实。处理切换对象、重复请求与卸载后的过期结果，不能让旧结果覆盖新对象。
- 身份、状态、错误与 requestId 沿用已有契约。业务授权、字段边界与生命周期不迁入展示组件，UI 校验也不替代服务端验证。

## 路由与现有功能

正式应用使用文件路由和正常 URL；原型 hash router、srcdoc 拦截器、SPROUT_PAGE 与场景 query 不进入产品运行逻辑。演示入口不得让访问者绕过认证或取得真实用户数据，生产构建和正式导航不暴露开发场景。

迁移遵循“先可用组件、再真实接入”的交付顺序。现有 loader、错误处理、保存和消息行为优先保留或明确搬移，不能为换 UI 删除 P3 运行、停止、仓库配置等已有能力。原有操作可达性和语义必须继续验证。

导航结构变化必须同步路由、入口、返回目标、直接打开、刷新、前进后退以及浏览器脚本的定位。可以更新旧 DOM selector 与已批准变更后的期望路由，不能通过删掉隔离、持久性、身份或错误断言来让验收变绿。

## 开发演示与版本记录

迁移时在 `src/dev/` 建立轻量的组件与页面场景入口，复用项目现有构建栈，不预先引入 Storybook 或另一套应用。入口应支持浅暗主题、指定场景、固定数据和独立复现，不依赖 OpenDesign 或个人绝对路径。

每个实际复用的基础组件提供它拥有的状态：Button 的默认 / pending / disabled，Field 的输入 / 错误 / 禁用，Dialog 的打开 / 关闭与焦点，业务页的正常 / 空数据 / 失败等。场景是可操作的实现证据，不只是静态截图，也不要求所有组件展示所有业务状态。

固定 fixture 位于开发演示内，使用明确的虚构样例。正式产品模块不能导入开发 fixture、模拟服务或归档代码。失败模拟清楚标为演示，不制造假 requestId 或假服务结果混入正式页面。

章节交付记录列出基线 commit、受影响 URL、组件及变体、场景运行方式、真实数据接入点、截图 / 交互证据和限制。源码与依赖进入版本管理；node_modules、临时日志和可再生的内嵌 HTML 不进入正式源码。

## 验证与交付

验证随风险选择，保留实际证据，不能仅凭“构建通过”判断 UI 正确。

| 改动 | 必要验证 |
| --- | --- |
| token、共享组件或布局 | 受影响演示及真实页面；浅暗主题；宽窄屏；焦点与状态；核对共享影响 |
| 表单与保存 | 校验、pending、防重复提交、失败保留输入、成功同步；真实接入后刷新验证 |
| 导航与分栏 | 直接打开、刷新、前进后退、Project 切换、手机列表返回、inspector 开关；隐藏筛选后不继续过滤 |
| 业务接入 | 真实请求与载荷、身份和持久性、未登录与跨用户反证、已有 P3 能力保留 |
| 纯文案或局部低风险外观 | 检查实际呈现，不为固定字符串或 class 列表新增镜像单测 |

布局或断点变化至少覆盖 390、901、1024、1199、1200、1440px，并额外检查被修改断点两侧。其余局部变更只检查受影响范围，不机械要求每个改动穷举所有宽度。长文本与长 ID、空数据、选中 / 聚焦和弹窗不能只用最理想样例验证。

代码改动运行 `pnpm check`、相关测试和必要构建；章节接入按总计划完成对应 verify 与独立技术验收。语义与布局回归优先通过真实浏览器验证，单元测试针对有回归价值的逻辑；不靠测试数量或读取源码断言 class 的方式证明设计正确。

视觉变化保存截图并实际读图；交互变化保留可复跑步骤或录像。没有查看截图，就写“未经视觉验证”；没有真机，就写“软键盘未经真机验证”。DOM 尺寸测量和 screenshot 文件存在不等于已经检查视觉。

`pnpm test` 已包含 `tests/frontend-boundaries.test.ts`：检查正式 TS 模块的静态导入、导出和字面量动态导入，以及 CSS `@import`，禁止依赖 `src/dev` 或 `design/archive`；检查组件和页面的颜色字面量、基础 Tailwind 色板与直接使用基础色变量的情况。`tests/design-tokens.test.ts` 核对语义 token 和变量映射，`tests/theme-preference.test.ts` 核对主题偏好。修改这些边界时用实际违规探针确认门禁会失败，再移除探针恢复通过。

这些检查针对源码中可识别的引用与颜色声明。布局、交互、信息层级、实际对比度和视觉一致性仍按上面的浏览器流程核对，不以正则或构建结果代替。

交付时说明本次呈现和行为变化、复用 / 新增的组件、验证结果、证据、未验证项与待确认决定。遇到已确认基线与代码不符，修复代码或明确记录迁移差异，不默默改写基线为实现让路。
